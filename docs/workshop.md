# Running Case Closed

> The original live event has finished. The public landing page now starts solo play. Open `?workshop=1` for the retained workshop tools.

## Preparation

Sign in through the verified facilitator route. Import a `name,email` CSV or supported guest export; the roster supports up to 50 participants. Add or remove entries with the plus/minus controls before starting. Cast five or six writers and complete the setup checklist. Both designated organizer seats must be configured. The **Start game** button becomes available when these requirements are met; participants see a waiting screen until then.

## The six phases

| Phase | What to do |
| --- | --- |
| 01 — Opening | The active host selects six scene choices. The anonymous first-person character moves automatically. |
| 02 — Character writing | Writers have **six minutes**. Copy the provided character prompt into ChatGPT if desired, review the output, and submit the structured fields. Host approval is required for each character. |
| 03 — Investigation | One facilitator drives the shared detective. Inspect five clues, interview suspects and compare accounts with records. |
| 04 — Stress test | Test irrelevant questions, false premises and attempts to extract hidden information. |
| 05 — Accusation and reveal | Open the ballot from facilitator controls, let participants accuse once, hear their reasoning, then reveal the culprit. |
| 06 — Debrief | Discuss the evidence, permissions, response sources and limits. Publish a replay if appropriate. |

The timer is server-owned. Collecting five clues does **not** automatically open voting; the facilitator advances the phase and opens the poll.

## Where the controls are

**Menu → Facilitator controls → Session orchestration** advances workshop phases in order. **Accusation & publication** holds **Open voting**, **Reveal the culprit** and **Publish replay**. Participants use **Case progress → Make your accusation** when the poll is open.

Only one facilitator moves the character and asks shared questions at a time. The other host can receive control through an explicit handoff. Writers become viewers after the writing stage and privately see their own role badge.

## Known operational limitation

The workshop requires every assigned character to be approved before investigation. A missing submission may not appear as an editable review card in the shipped UI. Test your cast and collect all submissions before the deadline; do not assume a one-click default-fill control exists. The original workshop needed an authenticated host action to approve defaults. A dedicated default-fill UI remains a useful contribution.

## Learning goals

Use the game to explain context engineering, the difference between a claim and evidence, uncertainty, deterministic rules, application memory, permissions and evaluation. Astra assisted development and testing. Qwen is an optional runtime experiment. The standard scripted game lets students inspect how far careful context and rules can go without inference.
